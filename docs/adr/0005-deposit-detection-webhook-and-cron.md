# 0005. Alchemy 웹훅과 cron 보완으로 입금 감지

- 상태: 제안됨
- 날짜: 2026-11-21

## 배경

사용자가 외부에서 USDC·USDT를 입금 주소로 보내면 거래내역에 입금 기록이 남아야 한다. 잔액 자체는 화면에서 RPC로 직접 읽으므로 감지가 늦어도 보이지만, 거래내역과 알림은 서버 기록이 있어야 한다.

웹훅만 쓰면 전송 실패나 서버 장애 때 기록이 빠질 수 있고, 블록을 직접 훑는 방식만 쓰면 지연이 크고 RPC 호출이 많아진다.

## 결정

- **실시간 경로**: Alchemy Address Activity 웹훅을 쓴다. 지갑 주소 등록 시 `/api/wallet-addresses/register`가 해당 주소를 웹훅 감시 대상에 추가한다. `/api/webhooks/alchemy/address-activity`는 네트워크별 서명 키로 HMAC 서명을 확인한 뒤 토큰 전송만 골라 기록한다.
  - 대상: 이더리움(USDC, USDT), Sepolia, Base, Base Sepolia(USDC).
- **보완 경로**: `/api/cron/deposits/base`가 Base와 Base Sepolia의 USDC `Transfer` 로그를 주소별로 다시 조회해 빠진 입금을 기록한다.
  - `CRON_SECRET` 베어러 토큰으로 호출을 제한한다.
  - 주소별로 마지막 확인 블록(`last_synced_cursor`)을 저장하고, 재조직(reorg)에 대비해 20블록을 겹쳐 다시 본다. 처음에는 최근 50,000블록부터 확인한다.
- 두 경로 모두 같은 기록 함수(`recordEvmTokenDeposit`)를 쓴다.
  - 웹훅 내용을 그대로 믿지 않고, RPC로 영수증을 다시 읽어 성공한 거래와 실제 `Transfer` 로그를 확인한다.
  - Aave에서 빼기로 돌아온 USDC는 입금으로 기록하지 않는다.
  - `체인 + 거래 해시 + 로그 위치`를 멱등 키로 써서, 두 경로가 같은 입금을 받아도 한 번만 기록된다.

## 검토한 대안

- **웹훅만 사용**: 단순하지만 누락을 복구할 방법이 없다.
- **cron 블록 스캔만 사용**: 누락은 없지만 지연이 크고 주소와 체인이 늘수록 RPC 비용이 커진다.
- **자체 인덱서나 The Graph 같은 인덱싱 서비스**: 유연하지만 지금 규모에 비해 운영 부담이 크다.

## 결과

- 장점: 평소에는 웹훅으로 빠르게 기록하고, Base USDC는 웹훅이 빠져도 cron이 채운다.
- 단점: cron 보완은 Base·Base Sepolia USDC에만 있다. 이더리움에서 웹훅이 빠지면 입금 기록이 남지 않는다.
- 단점: Arc, Kaia, Solana 입금은 서버에서 감지하지 않는다. 잔액은 보이지만 거래내역에 입금 기록이 생기지 않는다.
- 단점: Alchemy 정책이나 요금이 바뀌면 실시간 입금 기록이 영향을 받는다.
- 후속: 입금 기록이 필요한 체인을 늘릴 때 cron 보완 대상도 함께 늘린다.
